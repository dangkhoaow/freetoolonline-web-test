Depth: why each file type needs its own compression path

The reason a single compress button never fits every file is that each format already stores its own data differently, so the actual shrink has to happen in a tool built for that type. A photo in JPG, PNG, or WebP gets smaller by re-encoding its pixels, which is exactly what Compress Image does; a video, by contrast, needs a full re-encode through the Video Converter because wrapping footage a codec has already packed inside a ZIP barely changes its size. Office documents behave differently again: a DOCX, XLSX, or PPTX is already a ZIP archive under the hood, so zipping it a second time gains almost nothing - the practical move there is to leave the file as-is and pack it in a ZIP only when you want a single bundle for transport. PDFs sit in their own lane, where flattening or splitting through PDF Tools trims size more reliably than generic compression would. Routing by type this way keeps each job down to seconds for a typical file, instead of pushing everything through one path that helps photos but wastes effort on video and documents.
