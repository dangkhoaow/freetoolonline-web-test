Whether a frame is going into an image editor, a sprite sheet, or a static image fallback, the first practical decision is output format: PNG for transparency, JPG for size. PNG output preserves the per-frame alpha channel - edges stay clean against any background colour. JPG output is useful when the smaller file size matters, such as frames destined for a social post or a slideshow where lossless transparency is not needed. Three follow-on jobs for the extracted frames

Each frame lands as its own file in playback order, and that is what makes three follow-on jobs practical. To edit a single moment, open the numbered frame in an image editor, change it, and drop it back into the sequence at the same index - the sequential filenames keep the order intact, so nothing shifts around it. To build a sprite sheet for a game or animation asset, keep the PNG output so every frame carries its own transparency and tiles cleanly against any background colour. To replace a heavy animated GIF with a lighter static image on a bandwidth-limited page, pick one representative frame and export it as JPG, trading the alpha channel for a smaller file. Switching the output format never changes the number of frames - PNG versus JPG changes only the encoding, not the count.
