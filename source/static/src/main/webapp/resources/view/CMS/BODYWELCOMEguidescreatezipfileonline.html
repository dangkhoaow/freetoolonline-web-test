If you arrived here looking for a way to create a ZIP without installing anything on your computer, the creator above is the right answer: drop a folder or a selection of files onto the upload zone at /zip-tools/zip-file.html, name the archive in the Settings modal, optionally add a password, then click Convert and download the result. The whole round trip is a few seconds for most folders, and the source files do not stay on the build service - they are removed after a short retention window.

Which input shape and which password grade actually fit what you are about to send

The three input shapes the creator at /zip-tools/zip-file.html accepts are not interchangeable in practice: a single file is trivial, but a multi-file batch needs a Shift-click or Ctrl-click inside the file dialog to grab a run or a scatter of items, while dragging a whole folder onto the upload zone is the only path that preserves your sub-folder tree so the recipient unzips the same directory layout you started with. When you reach the Settings modal, the Archive name field defaults to the forgettable "archive.zip" - renaming it to the project name or a date range is the difference between a recipient opening it and treating it as spam, and sticking to ASCII letters with hyphens or underscores keeps the name intact across Windows, macOS, and Linux unzip tools. The password row is a genuine trade rather than a "higher is better" ladder: Standard ZIP encryption opens everywhere including decade-old software but is weak by current standards, AES-128 is the modern default that current Windows Explorer and the macOS Archive Utility both open natively, and AES-256 raises the cipher strength without changing that same compatibility ceiling, so an AES choice can leave a recipient on an old in-box unzip tool unable to open the file at all. One boundary worth setting expectations on before you upload: the creator builds and optionally encrypts new archives but does not open a .zip whose password is unknown, does not emit 7z or RAR, and passes input-file metadata such as EXIF, document author, and timestamps straight into the archive unchanged - clean those on your side first if the recipient should not see them.
