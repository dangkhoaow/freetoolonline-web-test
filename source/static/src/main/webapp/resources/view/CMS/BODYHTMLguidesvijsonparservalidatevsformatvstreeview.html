JSON parser online: kiểm tra vs định dạng vs vista cây - tính năng nào bạn cần?

JSON parser miễn phí trên trang này gộp ba tính năng: kiểm tra (bắt lỗi phân tích), định dạng (chuyển blob nhỏ gọn thành JSON để đọc), và xem cây (khám phá cấu trúc tương tác). Dùng kiểm tra trước, định dạng cho phản hồi nén, xem cây cho đối tượng lồng.

Câu trả lời 30 giây. Nếu JSON của bạn đang ném lỗi phân tích trong code hoặc trình chỉnh sửa tô đỏ, kiểm tra trước - parser tiết lộ vị trí lỗi đầu tiên. Nếu JSON của bạn là một dòng dài đã giảm thiểu sao chép từ tab mạng, định dạng nó - thụt lề làm cho phản hồi 50 dòng dễ đọc khi diff. Nếu JSON của bạn phân tích sạch sẽ nhưng bạn không tìm được khóa chôn trong các đối tượng lồng, dùng vista cây - mỗi thuộc tính trở thành một dòng bạn có thể mở rộng và kiểm tra. Khi nhiều hơn một áp dụng, thứ tự luôn là kiểm tra → định dạng → vista cây: lỗi phân tích chặn định dạng, và JSON không định dạng khó đọc ở dạng cây.

Khi nào kiểm tra trước

JSON parser kiểm tra khi bạn dán. Nếu input của bạn không hợp lệ, panel bên phải hiện thông báo đỏ Invalid JSON và chỉ vào lỗi đầu tiên. Bốn nguyên nhân thường gặp nhất là thiếu ngoặc ({ không có } tương ứng), dấu phẩy cuối ({"a": 1,} - JSON không cho phép), dấu ngoặc kép không thoát trong giá trị chuỗi ("key": "she said "hi""), và comment đi lạc (khối // hoặc /* */ - JSON không hỗ trợ comment). Sửa lỗi đầu tiên, dán lại, và parser cho bạn biết còn lỗi nào không. Kiểm tra chạy trước định dạng vì formatter không thể thụt lề JSON mà nó không thể phân tích.

Khi nào định dạng (làm đẹp)

Tính năng con định dạng / làm đẹp chuyển một chuỗi JSON một dòng đã giảm thiểu thành tài liệu được thụt lề đúng với mỗi thuộc tính trên dòng của nó. Dùng khi bạn sao chép phản hồi từ tab mạng, đầu ra curl, hoặc log server và cần đọc hoặc diff. Nút Copy Beautified JSON trả về cùng dữ liệu với thụt lề để bạn có thể dán vào review code, ticket, hoặc fixture test đơn vị. Định dạng không thay đổi dữ liệu - các khóa, giá trị, và hình dạng giống hệt input - chỉ khoảng trắng và xuống dòng thay đổi. Nếu bạn muốn hướng ngược lại (chuyển JSON đã làm đẹp về một dòng để gửi đi), cùng parser giữ cả hai dạng đồng bộ.

Khi nào dùng vista cây

Tính năng con vista cây render JSON đã phân tích thành cây tương tác trong panel bên phải. Mỗi thuộc tính là dòng riêng; đối tượng lồng mở rộng và sụp; mảng hiện các item theo chỉ mục. Dùng khi JSON phân tích sạch sẽ nhưng bạn không tìm được khóa chôn bốn cấp sâu, hoặc khi bạn muốn kiểm tra hình dạng của mảng - mỗi item có cùng loại, một số item thiếu trường, chỉ mục có khớp với cái API tài liệu? Bật Show Types để hiện loại của mỗi giá trị (string, number, object, array, boolean, null) bên cạnh khóa của nó. Bật Show Indexes để gán nhãn cho mỗi item mảng với vị trí base-zero. Vista cây chỉ đọc - không sửa đổi JSON trong panel input.

Khi nào dùng nhiều hơn một tính năng

Ba tính năng xếp theo thứ tự cố định: kiểm tra trước (nếu không formatter và vista cây thất bại), rồi định dạng (để phản hồi 200 dòng dễ đọc), rồi vista cây (khi văn bản đã định dạng vẫn quá dài để scan). Luồng công việc thông dụng khi debug API bên thứ ba: dán phản hồi thô, sửa lỗi phân tích đầu tiên mà validator hiện, nhấn Copy Beautified JSON để có bản sao dễ đọc cho ticket bug, và sau đó dùng vista cây để chỉ vào khóa cụ thể mà người tiêu thụ API mong đợi. Câu hỏi thường gặp

Vista cây có sửa đổi JSON của tôi không?

Không. Vista cây là render chỉ-đọc của input đã phân tích; bật Show Types hoặc Show Indexes chỉ ảnh hưởng cách cây được hiển thị, không phải JSON cơ bản. Để thay đổi JSON, chỉnh sửa panel input bên trái.

Sự khác biệt giữa minify và beautify là gì?

Minify xóa khoảng trắng, xuống dòng, và các ký tự không ý nghĩa khác để làm JSON nhỏ nhất có thể (để vận chuyển hoặc lưu trữ). Beautify (cũng gọi là "pretty-print" hoặc "định dạng") thêm khoảng trắng và xuống dòng để con người có thể đọc. Dữ liệu giống hệt trong cả hai dạng - chỉ định dạng thay đổi. Tương tự CSS cho code dùng hai công cụ riêng biệt: CSS minifier và CSS unminifier.

Tôi có thể dán JSON5, JSON-with-comments, hoặc NDJSON không?

Chỉ JSON nghiêm ngặt. JSON5 (cho phép comment, dấu phẩy cuối, và chuỗi với dấu ngoặc đơn), JSON-with-comments (đôi khi gọi là JSONC, dùng bởi VS Code), và NDJSON (một đối tượng JSON mỗi dòng) đều thất bại kiểm tra vì chúng không phải JSON nghiêm ngặt. Bỏ các tính năng không chuẩn trước, hoặc chuyển NDJSON thành mảng JSON, rồi dán.

Có gì được gửi đến server không?

JSON parser chạy trong trình duyệt của bạn; các lượt kiểm tra, định dạng, và vista cây thực thi trên client mà không upload JSON lên server. Điều này hữu ích khi JSON chứa dữ liệu nhạy cảm và bạn không muốn nó rời thiết bị.
