Tip: Logos and flat-colour icons trace cleanly; photographic PNGs almost never do.

What this tracer will not do. The PNG uploads to the processing service (it is not a pure on-device path), and traced lettering becomes path data rather than editable type. There are no trace settings to tune, so when the SVG balloons with thousands of segments the fix is a simpler or smaller input, not a slider. For real logo edits, start from the original vector file instead of a flattened PNG export.

In depth: which images vectorise cleanly, and which never will

The tracer has no controls, so the whole quality of the result is decided before you upload - by whether the image is the kind auto-tracing can follow. A flat two- or three-colour logo has large solid regions and hard edges, which is exactly what the tracer looks for: it draws one clean closed path per region, and the SVG stays small and stays sharp at any size. A photograph is the opposite - millions of subtly different pixels with no flat regions and no crisp boundaries - so the tracer carves it into thousands of overlapping slivers that render slowly and look blocky, and re-uploading will not fix that because the problem is the image, not a setting. Screenshots and gradients sit in between and usually trace into noisy, oversized files too. When a logo does come out heavier than expected, the lever is the input rather than a knob: start from a smaller or cleaner PNG, or re-export the source at a higher resolution so the edges are crisper. And when the graphic already exists as a real vector - an Illustrator, Figma, or Inkscape file - open that instead of tracing a flattened PNG, because tracing can only approximate the paths the original already holds exactly.
