Why a lookup is the only route back, and when it quietly returns nothing

The reason a lookup is the only route back is arithmetic rather than a missing feature: an MD5 digest is 32 hexadecimal characters drawn from a space of 2 to the 128th power, so nothing can walk that fingerprint backward to the text that made it. The To Text button on /md5-converter.html reflects this honestly - it never calculates the original string, it only reports whether this exact digest was paired with a plaintext at some earlier point. A common word like the literal password comes back at once because it was hashed long ago, while a 40-character random token you generated this morning returns an empty result, and that emptiness is the correct answer, not a failure to fix by retrying. When the text was never hashed anywhere before, the value is genuinely unrecoverable, and for a stored login the useful move is to leave MD5 for bcrypt or argon2id rather than keep hunting for a reversal that cannot exist.
