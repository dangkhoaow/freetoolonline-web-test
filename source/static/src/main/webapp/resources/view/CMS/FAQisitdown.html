Frequently Asked Questions

How does this checker test a website?

Your browser sends one direct request to the address you typed - from your own device and network, with an 8-second timeout. If the server answers at network level, the result card shows Reachable with the approximate response time in milliseconds; if not, it shows Not reachable with the reason. No third-party service receives the address, and this page does not store it.

Does "Not reachable" mean the site is down for everyone?

No. This is an "is it down for me" check with exactly one vantage point: your device. A failed check can mean the site is down, or that your network, DNS or an ad-blocker blocks it, or that the site refuses cross-site checks. Try a second network - phone data instead of Wi-Fi - before concluding the site itself is down.

The site shows Reachable but a page still errors for me - why?

Reachable means the server answered at network level - the front door is open. If a specific page or feature still fails, the problem is past the front door: a broken feature, a login or session issue, or your account. Hard-refresh, clear the site's cookies, or try a private window before anything else.

Why can this page not show an HTTP status code or an outage graph?

The cross-site request the browser is allowed to send is opaque by design: it confirms the server answered but hides status codes and page content. The page also keeps no outage history, uptime graphs or user-report counts - it is a point-in-time check from your device, not a monitoring service.

What do the popular-site cards at the top do?

Seven quick-check cards - Google, YouTube, Facebook, Instagram, X, Reddit and Wikipedia - run the same device-local check when the page loads. Each resolves to Reachable with its response time or to an honest not-reachable note; a card never goes blank. During a large outage this row answers "is it just me?" without typing anything.
