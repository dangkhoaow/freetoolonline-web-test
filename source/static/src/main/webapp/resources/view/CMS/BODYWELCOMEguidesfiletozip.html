More depth: wrapping one file for an upload that rejects the raw type

Wrapping a single file in a .zip is less about shrinking it and more about getting it past a gatekeeper. Plenty of mail servers and web upload widgets silently reject a raw .exe, .js, .bat, or .html attachment as a security measure, yet accept the identical bytes once they sit inside a .zip container. Drop the one file into the upload panel, click the Zip button, and the archive keeps the original filename and extension intact inside it, so the recipient extracts exactly what you sent. Expect the wrapper to add only a few hundred bytes of overhead: a 3 MB compiled binary or a 4 MB PDF comes back as a .zip of roughly the same size, because those formats are already encoded and have almost nothing left to squeeze. That is the trade the single-file flow makes - you gain a delivery envelope the receiving system will accept, not a smaller download, so reach for it when an upload form refuses your file type rather than when you need to fit under a size cap.
