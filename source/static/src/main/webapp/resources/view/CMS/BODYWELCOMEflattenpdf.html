Picking the flatten engine is the first practical choice on this page: ImageMagick handles layered PDFs that benefit from a uniform raster pass, while GhostScript suits vector-heavy files where the line work must stay sharp through the bake. When ImageMagick is selected, the density picker - 72 DPI for the smallest archive, 150 by default for general sharing, 300 when the result must stay print-ready - lets the same upload land at the right file-size and quality trade-off for each downstream use without re-running the upload.


The value of flatten is permanence and parity, not just byte-count: it is the one PDF operation here that bakes form fields, annotations, and layered content into the page itself, so a form-filled tax document, a signed contract, or a layered scan stays visually identical no matter which reader the recipient opens it in, and the once-editable fields no longer carry the risk of accidental edits on the way through. The server flatten step above needs no account or sign-in - the upload runs on an anonymous session, so there is no login between picking a PDF and starting the flatten. The download link that comes back is not permanent: the flattened file rotates off the server automatically a short time after processing finishes, so save it to your device before starting a second upload or closing the tab. Compress a PDF online for free: how flatten relates

Flatten is not a dedicated compressor, but the layer-merge usually reduces file size on layered PDFs as a side effect - signed contracts, scanned forms, and design exports often shrink noticeably once the layers, form fields, and annotations bake into one rendered sheet. The primary gain remains permanence and parity (every reader opens the file identically), and the byte-count drop comes for free on inputs that have many layers to begin with. For a strictly compress-oriented workflow on flat documents, pick a tool whose job is image or document compression, since flatten will not shrink an already-single-layer PDF.

What flatten does to fields, layers, and scans

Baking is one-way: there is no per-layer opt-out and no matching un-flatten step, so once the fields are baked the original interactivity is gone for good - keep the layered source file until you have confirmed the flat copy reads correctly in your own reader. Comments and highlight annotations are treated the same way as fields: they are drawn permanently onto the page surface, so a reviewer's markup becomes part of the sheet rather than a separate layer a later reader could toggle off or delete. Flatten does not add or remove a passcode, so a document that needs protection should pass through the password add or password remove tool first, then come back here to bake the remaining layers. A scanned page also stays a picture after the pass, because no text recognition runs during a flatten, so if you need selectable or searchable text you have to run the scan through a text-recognition step before flattening it.
