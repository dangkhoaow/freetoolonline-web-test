Name the archive before you download it. In the Settings panel, type a filename that reflects the project, the client, or the date - "myzipped-<date>" is the default but a name like "annual-report-2026" tells the recipient what they are opening before they unzip it. If the file list is empty when you press the Zip button, the page surfaces an inline error in the download row instead of producing a blank archive; re-add the files and try again. Small details like these turn a generic .zip into a bundle the recipient can read at a glance.

Depth: which ZIP encryption method to pick, and what the recipient needs

Before you press the Zip button, open the Settings panel and choose one of three encryption methods for a password-protected archive. Standard (the legacy ZipCrypto scheme) opens in every unzip tool ever made, but it is the weakest option and a determined attacker can brute-force it, so treat it as light obfuscation rather than real protection. AES-128 and AES-256 are genuinely strong; AES-256 is the safest choice, but the person receiving the file needs a modern extractor such as 7-Zip, WinRAR, or the macOS Archive Utility, because Windows File Explorer's built-in unzip cannot open an AES-encrypted archive and reports it as corrupt. Whichever method you pick, encryption scrambles the file contents but the AES methods also hide the internal file names, whereas Standard still leaves the entry list readable, so lean on AES when the listing itself is sensitive. Set the password in Settings, then send it to the recipient through a separate channel from the archive itself, a text message rather than the same email, because a password mailed alongside the file protects nothing. There is no password recovery here: if the passphrase is lost the contents are unrecoverable, and the remove ZIP password companion only helps when the password is already known.
