Pulling text out of a PDF instead

Images to PDF runs the opposite direction: photos become a new PDF, with no text layer extracted along the way. To pull readable text out of an existing PDF, open PDF to Text instead; that tool reads the document's embedded text stream and returns it as plain text you can copy from the page or download as .txt.

One important caveat on /pdf-tools/pdf-to-text.html: it does text extraction, not OCR. When the PDF was authored from a word processor or browser print, the text stream is already embedded and extraction is near-instant. When the PDF was scanned from paper or saved as image-only pages (like the output this Images-to-PDF tool produces), the text stream is empty and the extractor returns an empty result; a quick way to predict the outcome is to try selecting text in the source PDF first - if the cursor cannot select anything, the page is an image and PDF to Text will not recover the words. Image-only PDFs need a separate OCR step before extraction.

PDF or ZIP for sending a batch of photos: the tradeoff

When a batch of photos needs to reach someone who is not technical, one PDF beats a ZIP folder because the recipient double-clicks a single file and every viewer - Preview, Adobe Reader, a phone's default PDF app - opens it without an extraction step. A ZIP keeps every original photo at full resolution and file size untouched, which matters when the recipient needs to re-edit the source images later; a PDF flattens each photo onto a page at the size you pick in the Page size dropdown (Letter, A4, Legal, A3, A5, or Tabloid), so it is a presentation format, not an archive of originals. The in-browser panel on this page builds that PDF entirely on the device: pick images in the file picker, set Orientation to portrait or landscape and Margin to none, small, medium, or large, optionally turn on Page numbers, then click Convert - the images are rasterized to PNG and embedded page by page with zero upload to a server. For a mixed case - say, 12 scanned receipts that also need to stay editable later - keep the ZIP of originals for the records system and generate the PDF separately for the one-file email attachment, so neither workflow loses anything.
