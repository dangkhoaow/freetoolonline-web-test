Is It Down? Website Status Checker

Last reviewed: 2026-08-21

When a page will not load, the useful question is not "is the site down?" but "is it down for me?". Type any address into the box at the top - a bare domain like example.com or a full https:// URL - and press Check. Your browser sends one direct request to that site, from your own device and network, and the result card tells you whether the server answered and roughly how many milliseconds it took. No third-party checking service receives the address, and this page does not store it.

How to read a result honestly

A Reachable result means the site's server answered your device at network level - so if one specific page still errors, the problem is past the front door: a feature, a login, or your account, not the whole site. A Not reachable result is genuinely ambiguous, and the card says so: the site may be down, or your network, DNS or an ad-blocker may block it, or the site may refuse cross-site checks. The quickest way to settle it is to try a second network - switch from Wi-Fi to phone data. If the site loads there, your network was the blocker; if it fails on two networks, a real outage is likely, and waiting usually beats changing settings. A check that gets no answer within 8 seconds reports as timed out, which can look identical for an overloaded site and an aggressive firewall - retry once before concluding anything.

Popular sites at a glance

Below the input, seven quick-check cards - Google, YouTube, Facebook, Instagram, X, Reddit and Wikipedia - run the same device-local check when the page loads. Each card resolves to Reachable with its response time, or to an honest not-reachable note naming the possible causes; a card never goes blank. During a big social-platform outage this row answers the reflex question in one glance, without typing anything.

What this page can and cannot tell you

This is an "is it down for me" check, not a global outage monitor: the probe runs from exactly one vantage point - your device. Because the browser's cross-site request is opaque by design, the page can confirm the server answered but cannot read HTTP status codes or page content, and it keeps no outage history, uptime graphs or user-report counts. A site that refuses cross-site checks can show as not reachable here while opening normally in a tab - the result table under the tool spells out each case in plain words, and a numbered checklist walks through what to do when a site will not load. Everything works in the browser with no app install and no account.
