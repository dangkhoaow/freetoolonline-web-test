One password, and it unlocks everything

PDF security has two password concepts: a user password (open password) that blocks opening the file at all, and a separate owner password (permissions password) that some tools use to restrict printing or copying once the file is already open. This tool sets only the open password - the single password you type is required before any page renders. It does not offer a second, different owner password, so once someone enters the password they can view, print, copy, and edit the file freely; there is no way with this tool to keep a document readable while blocking printing or copying.

Signing a PDF that already has an owner password? That is the restriction that blocks most signature tools, not the open password this tool applies. Remove it first with Remove PDF Password, then sign - see How to sign a PDF after removing its password for the order of operations.


Choosing a PDF password that resists common attacks

Target twelve characters or more, mixing cases, digits, and at least one punctuation mark. Avoid dictionary words, dates tied to the document, and strings derived from the filename. A passphrase of four unrelated words is the strongest memorable option. For archival documents, consider a second layer - a ZIP password blocks the byte-level file even before the PDF viewer runs. The encryption is a 128-bit key; since only one password exists here, that password - not the cipher - is the part worth making strong.


Privacy and how this tool handles the password you set

To encrypt the PDF, the file is uploaded over HTTPS to our processing service along with the password you enter. The service generates an encrypted copy and returns a download link. Files are removed after a short retention window.

Need the inverse workflow? To remove the password from a PDF you're allowed to open, use Remove PDF Password (you still need to know the password). If you're encrypting a form-filled document, run Flatten PDF first so filled fields and annotations become part of the final page content before the password layer is applied.

Need the owner-password / permissions behaviour instead? This tool does not offer it. Read PDF password types - owner vs user for the general distinction - the user password blocks opening; the owner password restricts copy/print after the file is open - so you can confirm whether the open-only lock this tool applies is actually what the task needs.

Send the password separately from the file

Once the encrypted copy comes back, that password is the only key that opens it - there is no recovery path if it slips your mind, so treat it like a real key rather than a note in the same email. Pass it along through a different channel than the one carrying the PDF itself, a text message or a spoken word in person, so a single compromised inbox cannot unlock both pieces at once.

A password and a redaction solve different problems: the password on this page controls who can OPEN the file and can be removed later by anyone who knows it, while the Redact PDF tool permanently DELETES the marked content for every reader, with no way back. For a document that must circulate widely with certain lines removed, redact first - then encrypt the result here if access control is also needed.
