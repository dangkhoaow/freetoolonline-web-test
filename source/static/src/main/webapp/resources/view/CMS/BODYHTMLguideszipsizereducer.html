Where the in-browser ZIP reducer lives

The actual reducer is the in-browser ZIP creator at /zip-tools/zip-file.html. This guide explains when "reduce ZIP size" actually saves space; the tool page is where the archive is built. The flow is the same in either direction: upload a single file, a multi-file selection, or a whole folder (sub-folders preserved); the page bundles everything into one ZIP and returns a download link.

The quick size-win heuristic

The quick size-win heuristic for the ZIP size reducer: group compressible files (logs, CSV, JSON, source, plain text, BMP/TIFF) together before zipping - already-compressed JPG, PNG, MP4, and PDF rarely shrink inside a new .zip envelope.

What the reducer cannot do

What the reducer cannot do is re-encode the bytes inside each file: ZIP File Creator wraps an archive around what you give it. A 4K JPG stays roughly the same size inside the .zip; shrink photos with Compress Image first if size is the goal.

Optional password and encryption setting on the reducer

Optional password and encryption setting on the reducer: ZIP File Creator can lock the archive in Settings - Standard, AES-128, or AES-256 - then you download the protected .zip; remember the password yourself because this page does not store it.
